# 心率采集模块（HPM5300EVK + MAX30102）

座舱里「心率」那一格的整条来路。**本目录自成一块**：板端固件、接线、串口协议、PC 侧算法、
验收命令都在这里；唯一的例外是 PC 侧那份代码 —— 它是界面服务器的一部分，住在 `ui/`。

```
MAX30102（I2C 0x57，100 Hz，18 bit，RED+IR）
  → hr/firmware/         HPM5300EVK，I2C0 轮询，每行打一个样本
  → UART0 @115200        D,<t_ms>,<red>,<ir>
  → ui/serial_hr.py      PC 侧算心率（带通 → 峰检 → IBI 中位 → 质量闸；被拒时走频谱兜底）
  → ui/state.py 的 st.hr
  → index.html #rHr / detail.html #mHr / monitor.html #mvHr 三格，以及小瑞的上下文
```

心率是**纯显示字段**：只写 `st.hr` 一个字段，不进告警、不进 `src/fuse.py` 的融合。
算不出来时三格显示「未接入」。

```
hr/
├─ README.md          ← 本文件：从接线到验收的入口
├─ probe.bat          一键：手指按住传感器跑一遍裸量探针（要先关界面）
├─ live.bat           一键：实时小窗口，波形 + 直流 + 五道门判据（要先关界面）
├─ check.bat          一键：PC 侧算法自检（不碰串口，界面开着也能跑）
├─ ui.bat             一键：起网页界面
└─ firmware/          板端固件（独立 cmake 工程）
   ├─ README.md       寄存器旋钮、两条故意偏离 Maxim 参考固件的地方
   ├─ build.bat       生成 + 编译
   ├─ flash.bat       烧进板上 QSPI NOR
   ├─ src/            main.c / max30102.c / max30102.h / print_nb.h
   ├─ tools/          openocd_hpm5300evk.cfg
   └─ logs/           旧位置的构建与烧录记录（历史快照，不会被覆盖）
```

## 1. 硬件与接线

| 模块引脚 | 接到 |
|---|---|
| VCC | **3.3 V** |
| GND | GND |
| SDA | **PB03** |
| SCL | **PB02** |

- ⚠️ **VCC 决定 I2C 电平**：模块自带的电平转换按 VCC 做。接 5 V 时总线也被抬到 5 V，
  而 HPM5300 的 IO 是 3.3 V —— 必须接 3.3 V。
- ⚠️ **模块自带 10 kΩ 上拉**，不要再外挂一组（并联把上升沿拉坏）。
- 这四根线和 MPU6050 完全一样，同一个 I2C0（`BOARD_APP_I2C_BASE`）。
- **INT 没接**（只接四根），所以固件不开任何中断使能位。
- 从机地址 `0x57`，`PART_ID(0xFF)` 应为 `0x15`。

## 2. 串口

`115200 8N1`，FT2232 的 **channel B**（设备管理器里的 `USB Serial Port (COMn)`）。
COM 号随插拔变，**PC 侧按 `VID:PID=0403:6010` 认端口，不认 COM 号**
（板载 FT2232，channel A 走 JTAG，channel B 才是这路串口）。

⚠️ **串口是独占设备**：界面（`ui/run_ui.bat`）开着的时候，别的进程打不开它 ——
报的是 `PermissionError(13)`，那句在说「界面开着」，不是板子坏了。

## 3. 协议（板子 → PC）

| 前缀 | 含义 |
|---|---|
| `#<text>` | 状态/横幅，人读的，PC 侧只记日志 |
| `D,<t_ms>,<red>,<ir>` | 一个样本，100 Hz，两个通道都是 18 bit |
| `E,1,<text>` | 芯片没答话 / 初始化失败（`stat=3` = status_timeout） |
| `E,2,<ovf>` | FIFO 溢出计数变了 = 中间真丢了样本 |
| `E,3,<text>` | I2C 读失败（会自己重新初始化，拔了再插能自愈） |
| `H,<t_ms>,<hr>,<rmssd>,<pi>` | **板端自己算的**三个量，1 Hz（2026-09-26 加）。量不出来打 `--` |

行里带 `t_ms` 是必需的：`print_nb()` 拥塞时**整行丢**，只有时间戳能让 PC 侧知道中间缺了多少 ——
少了它，「丢了一半样本」和「心率真的变慢了」在 PC 侧长得一模一样。

`red` 这一路心率用不上（心率只看 IR），一起打出来是为了 SpO₂ 和「两个通道是否同时受扰」的诊断。

### 关于 `H,` 行（2026-09-26 加）

存在理由是用户那句「在 segger 串口再来三列输出这个」—— 串口是**单向**的，
PC 上算出来的数回灌不进 SES 那个终端，所以要看得见就只能板子自己再算一遍。

🔴 **`D,` 行一个字节都没动。** 这不是风格问题：`ui/serial_hr.py` 里是
`if len(f) != 4: bad_lines += 1` —— 往 `D,` 后面加一段，**每一行都被算成坏行**，
界面上心率那条路当场全死。所以新量另起一行。

🔴 **两边各算各的，谁也不许"修正"谁。** 页面上的数**只认 PC 那份**（它多了频谱兜底、
五道门、化石修复，都验过）；板端这份只出现在这个终端和交叉校验报告里。

⚠️ **`H` 行的 `hr` 会经常是 `--`，那是诚实的不是坏的。** 板端没有频谱兜底，
而 PC 主路的三道门拒得很凶。同理 `rmssd` 在手指刚按上的头 30 秒**必然是 `--`**
（要连续 NN 跨度 ≥ 30 s），这是用户点名要的「前 30 秒显示横杠」。

比例参考（`_scratch/_hr_board_ab.py` 在 90 秒真人实录上跑的）：`hr` 85/91、
`rmssd` 25/91、`pi` 89/91 条有数。

🔴 **但 `rmssd` 那 25 条「有数」不能照着下结论 —— 而且当晚更晚一次复算把我当时写的
归因推翻了。以下是更正后的版本。**

**先纠正我写错的那一条：「根因是搏动检测器在漏检/多检之间抖」在录下来的这段上不成立。**
把 `runs/_hr_nn_20260926_205912.txt` 完整复算（`_scratch/_hr_jitter.py`）：

```text
间隔落位   98.4% 落在 330~1600 ms 内（62/63）；平均 982.7、中位 980.0（差 0.3%）
拍数对照   频谱说这 61.9 秒该有 65.6 拍，实到 64 拍（差 1.6 拍）
```

两条**互相独立**的判据都说总数没大错 ⟹ 这段录音上检测器是好的。

⚠️ 复算的坑（我自己先踩了）：统计量要拿 `diag()` 里 `beat_times` 的**全部相邻拍**，
**不能**拿 `ibis`。`ibis` 是 `deque(maxlen=BEATS_KEPT=8)`，它的长度**永远是 8**
—— 当成"被采纳的间隔数"会得出"90 拍只采纳了 8 个"这种荒唐结论（我第一版就是这么
写错的）。`beats` 计数器**不被 `_reset_beats()` 清**，所以它比环里的拍数多，多出来的
是手指上来**之前**的噪声拍。

## RMSSD 在页面上一直是 `--` 的真因：**攒不够 30 秒**

```text
链最长到过   31.040 秒（在 t=75.3 s）；中途断链 2 次
第一次够格   t = 66.0 秒（之后一连 26 拍都够）
```

闸是**连续不断**攒够 30 秒。这段 90 秒的录音里，要到**第 66 秒**才第一次够格。现场
演示按不到一分钟、或者中途动一下链就从头攒 ⟹ 屏幕上**永远是 `--`**。

**这不是算法不出数，是还没攒够。** 这一条同时解释了「很长时间了 HRV 还是没有」。

## ⚠️ 2026-09-26 深夜：页面上那一格**已经换掉了**，RMSSD 不再上屏

上一节那个后果被用户当场看见并要求改掉 —— 屏幕上永远一根横杠，他的原话是
「算了 那地方换个数据吧 换个一直有的」。四个页面（index / detail / monitor / data）
的 `HRV-RMSSD` 换成了 **脉搏波幅度**（`state.hr_ac` = `_HrTracker.ac_rms()`，
带通后的交流 RMS；单位是 ADC 计数、无量纲，界面上**不给单位**）。

- **为什么是它**：同一场实时会话日志（`runs/_hr_live_20260926_223242.log`）按帧数
  统计「有数占比」——`rmssd` **0.0%**、`ac_rms` **100%**、`pi` 100%、`beats` 100%、
  `hr` 96.1%。它和心率的相关 r=−0.20（独立）、和 PI 只中度相关 r=+0.55
  （PI 就是它除以直流），换上去不和已有两格重复。
- **RMSSD 本身一行代码都没删**：`snapshot()["rmssd"]` 照旧产（实时窗口 `hr\live.bat`
  的 `S` 行日志照旧记它）、板端 `H` 行照旧算。只是**页面上没有它的位置**了。
- 上面两节（那道闸、剔除异常拍、以及"别调小 30 秒"）**全部照旧有效** —— 它们是关于
  RMSSD 这个量本身的结论，与它显不显示无关。

## 出数之后那个值也不能直接用

```text
rmssd() = 251.3 ms
但链上 32 个 NN 的一阶差分里，最大的 3 个占了 Σd² 的 91%
那 3 个全部来自一对 350 → 1470（和 = 1820 ≈ 2 × 中位 980）
把跨过那一对的三个差分剔掉：RMSSD = 143.3 ms
```

RMSSD 是**平方和** —— 一次异常拍就能盖过其余 28 个。那对 `350+1470` 是**代偿间歇**的
形状：一次真早搏，或一次劈拍（一拍登记成两下）。**这两者在间隔序列上不可分**（和
`MAX_IBI_SPREAD` 被推翻是同一条道理），但**处置相同**：HRV 的标准做法本来就是剔除
异位搏动 / 伪间隔。

⚠️ 但**剔完还剩 143.3 ms** —— 说明其余那些拍本身也不算干净，**不是「剔掉那一下就
好了」**，别指望一个过滤器救回全部。990 ms 的均值上相邻差动辄 ±190 ms（19%），
这个幅度偏大，有两种来路：真人确实有大幅 RSA，或**检测时刻被某个慢变量调制**
（搏动幅度随接触压力漂 ⟹ 过阈时刻跟着漂）。**离线分不开这两者。**

⟹ **不要靠"调小 30 秒那道闸"来让它出数** —— 那道闸正拦着 143~251 ms 这个数，
调小它 = 往串口和页面上放一个假数。这一点原来的结论不变，变的是**为什么**：
不是"检测器坏了要治"，而是**要先能分开上面那两种来路**。那需要一段**带波形的
实录**（`hr\live.bat`，它画带通后的波），离线做不了。

## 4. 编译 / 烧录

```bat
cd hr\firmware
build.bat            :: 生成 + 编译，软浮点（默认，就是板子上跑的这份）
flash.bat            :: 烧进板上 QSPI NOR（先跑 build.bat）
flash.bat reset      :: 只复位重跑
```

产物：`hr\firmware\build_hpm5300evk_flash_xip_debug\output\demo.elf`，
SES 工程在同目录的 `segger_embedded_studio\hr_node.emProject`。

**采集中间那段热路径里一个浮点都没有**（DMA ISR → 两个环 → `D` 行，全是整数）。
但 `H,` 行加进来之后，`src/hr_algo.c` 里有一份三节双二阶（软浮点下约 2000 cycle/样本，
100 Hz 下是 480 MHz 核的 0.04%）—— 所以**现在链 libm 了**，而默认的软浮点构建
仍然是正式那份；`hf`（硬浮点）只是和 CAN 工程对齐用的，**不烧**。

⚠️ `CMakeLists.txt` 里给 `src/hr_algo.c` 单独加了 `-ffp-contract=off`（**只给它**，
`main.c`/`max30102.c` 没有）。这条**不能靠"rv32imac 没有 F 扩展"来省**：哪天切到
`hf` 那份，FMA 收缩会让双二阶在某些样本上差一点，而且是查不出来那种差。
`_scratch/_cl.bat` 那边的对应物是 `/fp:strict`。

⚠️ 两个 bat 都从 `%~dp0` 推出自己的位置和 `BUILD_DIR`，所以**整个 `hr\` 目录可以搬到
任何地方，两个 bat 一个字都不用改**。唯一要守的规矩是：`build.bat` 与 `flash.bat`
里那段 `BUILD_DIR=...` 的推导**必须写得一样** —— 两边指向不同的目录时，
`flash.bat` 会报「demo.elf not found」，看着像没编译，其实是找错地方了。

## 5. PC 侧

`ui/serial_hr.py`（纯 `math`，没有 numpy）。读线程按 `VID:PID` 找口、自己重连、不抛异常，
所以网页永远打得开。

**两条路**（2026-09-26 加第二条）：

| | 做法 | 什么时候用 |
|---|---|---|
| 主路 `_HrTracker.bpm()` | 带通 → 峰值保持包络 → 阈值跌回登记 → 8 拍 IBI 中位数 → 质量闸 → **时效** | 首选，灵敏 |
| 频谱兜底 `_HrTracker.spec_bpm()` | 带通后抽取到 25 Hz，在 0.8~2.5 Hz 上直接算 DFT 取基频 | 主路被质量闸拒时 |

兜底存在的理由：**多检/漏检在间隔序列上长得一模一样**，所以「间隔规不规整」回答不了
「这个率准不准」。而多检/漏检都不挪动频域里基频的位置 —— 频谱法对这两种错天生免疫。
它有自己的毛病（运动幅度被低频调制时会自信地报错），**所以只兜底、不替换主路**。

**三道门**（2026-09-26 补后两道，治用户报的「心率还不是实时的」）：

| 判据 | 值 | 治什么 |
|---|---|---|
| `MAX_IBI_SPREAD` | 0.20 | 这串间隔像不像心跳。⚠️ **它分不开好和坏** |
| `IBI_FRESH_S` | 4.0 | **化石**：主路原来对输入没有任何时效检查，8 个间隔不再进新值也照报不误（屏幕上那个不动的数就是它），而且非 None 就把兜底挡住了 |
| `AC_MIN_RMS` | 20.0 | **噪声里"找到"搏动**：峰值检波的阈值是相对量（`PEAK_FRAC × env`），输入只剩噪声它也照样出数。时效治不了它 —— 噪声确实在不停产生搏动 |

关键常数（都在 `ui/serial_hr.py` 顶部，都写着来历）：

| 常量 | 值 | 说明 |
|---|---|---|
| `SAMPLE_RATE_HZ` | 100 | **必须等于板端 `MAX30102_SPO2_CFG` 选的采样率** |
| `BP_LOW_HZ` / `BP_HIGH_HZ` | 0.65 / 3.5 | 4 阶巴特沃斯高通 + 单节低通 |
| `MIN_BEATS` / `BEATS_KEPT` | 4 / 8 | 少于 4 次搏动不出数（「攒心跳中」） |
| `MIN_IBI_S` / `MAX_IBI_S` | 0.33 / 1.60 | 有效间隔范围（180~37 BPM） |
| `MAX_IBI_SPREAD` | 0.20 | 质量闸。⚠️ **它分不开好和坏**，见 `serial_hr.py` 里的证据表 |
| `IBI_FRESH_S` | `MAX_IBI_S × 2.5` = 4.0 | 主路时效。**比的是样本钟**（板子时刻），不是墙钟 |
| `AC_MIN_RMS` | 20.0 | 带通后的交流下限。实测：真手指 498、这块板子的带内噪声 5.6 |
| `FINGER_DC_MIN` | 20000 | 手指没按上去时 IR 直流只有几千 —— 低于它就是「没手指」 |
| `SPEC_*` | 见文件 | 兜底：10 s 窗、0.8~2.5 Hz、步长 0.0025 Hz、抽取 ÷4、最快 1 s 重算一次 |
| `STALE_S` / `REOPEN_S` | 1.5 / 3.0 | 串口停了就报停；3 s 后重开串口 |

`hr` 为 `None` 的几条来路（屏幕上都是「未接入」，但原因不同）：

| 显示 | 真因 |
|---|---|
| 未接入 | 没插串口 / 串口没在出数 / 串口停了 |
| 未接入 | 手指没按上去（IR 直流 < `FINGER_DC_MIN`）—— 板子在出数，是**传感器**没信号 |
| 未接入 | 传感器上没搏动（交流 < `AC_MIN_RMS`）—— 手压着或环境光饱和，但没有脉搏 |
| 未接入 | 攒心跳中（有效间隔 < 4）/ 两条路都说不出话 |

**一个 D 样本都没进来**（板子侧没通）和**手指闸没过**在屏幕上长得一模一样 ——
分它们只能靠 `probe.bat`，而且判序必须先看「有没有样本」再看「手指」。

## 6. 一键跑

```bat
hr\ui.bat        :: 起网页界面（= ui\run_ui.bat），心率在三格上实时跳
hr\live.bat      :: 实时小窗口（不经过浏览器）：波形 + 直流曲线 + 五道门的判据
hr\probe.bat     :: 关掉界面之后，手指按住传感器，跑一遍裸量探针
hr\check.bat     :: PC 侧算法自检，不碰串口
```

`probe.bat` 的结论只有一句，在 `runs\_hr_finger.log` 里：
**出数了 / 一个样本都没进来（板子侧没通，跟手指没关系） / 手指闸没过 / 攒不到心跳 / 质量闸一直在拒** ——
这五种在界面上完全一样，只能这么分开。

`live.bat` 开的是**独立窗口**（matplotlib + Tk，跟浏览器一点关系都没有），画三样：

- **脉搏波** —— 就是 `_HrTracker.slow`，带通之后、抽取到 25 Hz、最近 10 秒；
  红点标的是算法**真正登记**的那些搏动（所以舒张期那个小鼓包不会被标上，
  一眼能看出"它是怎么数拍的"）。
- **IR 直流趋势** —— 最近 60 秒。手指闸那条点线就画在门槛上：直流够不着它，
  说明手指没按到位；够得着才轮到后面几道门。
- **五道门的判据值 / 门槛 + 过没过** —— 屏幕上没数的时候先看这一行，
  是哪道门在拦、还差多少，都写在上面。**阈值是从 `serial_hr.py` import 的**，
  不是窗口里另抄一份，所以不会各说各话。

⚠️ **它自己开 COM9，跑之前必须把界面关掉。** 界面开着时窗口顶上会一行红字
「串口被占（界面开着？）」—— 那句话是在说"界面占着口"，**不是板子坏了**。
⚠️ 串口一停，那些缓冲里还留着旧值，照画会画出一条**看着很合理但其实冻住**的波形
（就是"化石"的图形版）。所以一律**整幅画成灰的并标注「陈旧」**，不许装作还在动。
按 `q` 或 ESC 退出（直接关窗口也行）；退出时会等读线程把串口放掉再返回，
所以紧接着就能把界面开回来。

### 6.1 会话日志（2026-09-26 加）：**每次会话落一份，能离线复算**

用户原话：「**你肯定要落日志啊 不然你看什么**」。这话是对的 —— 窗口原来
**只画不记**，出了问题只能在屏幕上读**一个瞬间**：链子是**在哪一拍**断的、
`NN跨度` 是一格格涨的还是反复从零重来、USB 有没有丢样，看完那一瞬就没了。
而上面那个**未决**（离线 `31.0 s / 断 2 次` vs 实时 `12.0 s / 断 13 次`）就卡在
这儿：**没有实时的拍序列，两边永远对不上**。

每跑一次 `hr\live.bat` 就落一份 `runs\_hr_live_<日期>_<时分秒>.log`
（**一份一个文件名，绝不覆盖上一份** —— 这个项目里 `runs/_hr_raw.txt` 被覆盖过
一次，代价是那次现场的证据整个没了）。`--log <路径>` 可以指到别处。

三类行，逗号分隔；`#` 打头是注释/表头/脚注。列名纯 ASCII，量不出来一律 `--`
（和串口 `H,` 行同一条规矩，**不用 0 顶替**）：

| 行 | 频率 | 内容 |
|---|---|---|
| `S,` | 约 1 Hz | 状态快照：`dc` / `ac_rms` / `spread` / `beats` / `ibi_age` / 主路 / 兜底 / `hr` / `finger` / `nn_n` / `nn_span_ms` / `rmssd` / `pi` / 行数 / 坏行 |
| `B,` | 每一拍 | `beat_ms`（那拍的板子钟）、**它和上一拍的差**、`nn_n`、`nn_span_ms` |
| `T,` | 1 Hz | 步长直方图（`dt_ms:次数`，前 6 名）+ 累计样本数 / 往回跳次数 / 最大间隔 |

🔴 **`B` 行记的是 `beat_times`（所有登记到的拍），不是 `nn_ms`。**
`_HrTracker` 只留下**被收下**的间隔 —— 掉出 `[0.33, 1.60]` s 的那个间隔它**根本
不存**。而"链子是在哪一拍断的"恰恰由**被拒的那些**决定：记 `nn_ms` 就正好把要查
的东西丢了，日志会看着很干净而问题全隐身。

🔴 **步长统计写在读线程上（`LiveHr._feed`，100 Hz），只做整数自增和字典计数。**
一旦在那儿落盘，一次写阻塞就把读循环拖住 —— **制造出它本来要测的那个丢样**。
真正的落盘在绘制线程（`poll()` → `HrLog`）。这条是刻意的，改之前先想清楚。

读回来：

```bat
D:\Anaconda3\envs\dms\python.exe _scratch\_hr_live_log.py
    :: 不给路径就读 runs 下最新那份。**不碰串口，界面开着也能跑。**
```

它算出四件事（人眼扫 CSV 扫不出来的那些）：① 步长（丢样的直接判据，未决的头号
假设就靠它）；② **链子最长到过多少、断了几次、到底够没够 30 秒** ——
这是「HRV-RMSSD 那格为什么是 `--`」的唯一直接答案；③ 那串间隔落在
`[0.33, 1.60]` s 里的比例、有没有**长短交替**（离线"一处劈拍" vs 实时"全程交替"
是两回事，先量出来是哪种）；④ 从被收下的 NN 上**独立复算**一遍链子和 RMSSD，
和日志里板端自己算的那份**对拍** —— 对不上就说明"文档写的规则"和真跑的
不是一回事，那一句会直接喊出来。

判据全部从 `ui/serial_hr.py` import，**不在这里写第二份阈值**。

### 6.2 `NN跨度` 那一行（2026-09-26 加）

窗口的判据行原来那五道门（直流/交流/离散度/有效拍/时效）**全是 `hr` 那一路的**，
决定 RMSSD 出不出数的那个值（连续 NN 跨度）**一行都没画** —— 屏幕上的 `--` 有
"手指不在位 / 链子没连起来 / 就差几秒"三种来路，长在屏幕上一模一样。所以补了
一个 `NN跨度 <秒>/30 过|否` 条目。

⚠️ 它**不参与 `whole`**：链子没攒够是**常态**不是故障，让它把整行染红会盖掉
上面那五道门真正的红。

### ⚠️ 三个板端诊断从未被真跑过并留档（2026-09-26 决定：不专门去拔线验）

## 8. 现状与未决

- ⚠️ **「卡在 119.9 不动」的机制已经修掉，但那个具体的 119.9 没有坐实。**
  2026-09-26 实测：20 秒 159 帧里 `hr` 只有 1 个值（119.9），同一帧里
  pitch/ear/mar/p_fat 全是 159 个不同的值 —— 所以 tick 是活的，冻的只有心率这一路。
  读代码 + 离线复现（`_scratch/_hr_fossil.py`）确认了**机制**：主路 `bpm()` 是那 8 个
  间隔的纯函数、**一个时间项都没有**，信号一没它照样把上次的中位数一直报下去，
  而且非 None 就把兜底整个挡住。修法就是 `IBI_FRESH_S`。改后同一个场景
  无脉搏段从「100% 都挂着数、最长冻 12.5 秒」变成「4%、最长 2.5 秒」。

  但**那一次是不是同一回事，没有原始数据能证明**。原来记的主假设「双计」也**没被证实**
  —— 冷下来看，双计会让数字抖动而不是纹丝不动，所以那个假设反而更可疑了。
  要坐实得在**冻住的那一刻**占串口录一段原始 IR（`probe.bat`），看三件事：
  `dc` 落在哪（手指到底在不在）、`ac_rms` 多大（低于 20 就是新加的这道门在管）、
  `beat_times` 的相邻间隔（双计会是极规整的 T/2）。**界面开着的时候做不到。**

- ⚠️ **两道门都拦不住的一种**：真有大幅度的带内干扰（运动伪影、环境光闪烁）而且峰还规整
  —— 它会报一个**会动的**错数（不是冻住的，是乱跳的）。PPG 没有加速度计做参考运动消除，
  这件事靠阈值解决不了。**没有量过**这种情形，不要假装它被覆盖了。

- ⚠️ **`AC_MIN_RMS` 的"没有脉搏"那一侧是合成噪声**：这块板子真实量到的"没有脉搏"
  只有空载（直流 8450，交流 8.7），而它是被手指闸拦的、走不到这道门。
  「手指拿开、只有环境光、而直流仍然高」那一种**没量过**（要独占串口）。
  真饱和若把带内噪声顶过 20，这道门拦不住 —— 那时还有时效、离散度闸、兜底量程边三道兜着。
- **SpO₂ 没标定**：`red` 通道一直在打，但没算 R 比值，界面上血氧那一格是静态的 ——
  给一个没标定过的数等于编数。
- **温度寄存器没读**（`0x1F`/`0x20`）。
- `_check_hr_ui.py` 在 8790 上**界面关着的时候**会红：它那条判据的前提（demo 源 ⇒
  `hr` 是 None）不成立，因为 hr 和 `--source` 无关。判据要改（见第 7 节），
  产品侧没问题。
- 首次在真人手指上采数时，第一件事是看 IR 直流落在哪：不到 `FINGER_DC_MIN` 就先调板端
  `MAX30102_LED_PA`（`hr\firmware\src\max30102.h`，步进 0.2 mA）。
