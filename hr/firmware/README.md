# 心率节点固件（HPM5300EVK + MAX30102）

> 本文件只讲**板端**：寄存器旋钮、以及两条故意偏离 Maxim 参考固件的地方。
> 接线、串口、协议、PC 侧、验收、现状 —— 全在上一层的 [`../README.md`](../README.md)。

板子只干一件事：**把 MAX30102 的原始计数按行打到串口上**。心率是 PC 侧算的。

```
MAX30102 FIFO（100 Hz / 18 bit / RED+IR）
  → 本工程（I2C0，PB02=SCL PB03=SDA）0.5 ms 轮询
  → UART0 @115200，每行一个样本：D,<t_ms>,<red>,<ir>
  → dms_project/ui/serial_hr.py 算心率（带通 → 峰检 → IBI 中位 → 质量闸；
     被闸拒时改走频谱兜底）
  → 网页端三个页面的「心率」格；算不出来时显示「未接入」
```

**2026-09-26：本工程复制了一份到 `dms_project\hr\firmware\`**（心率模块要自成一块）。
换位置对编译是安全的（路径全相对、SDK 靠 `$ENV{HPM_SDK_BASE}` 找），实际验证过：
新位置重新编译出的机器码和原位置**逐字节相同**（只有 `__TIME__` 横幅那 4 个字节和
两个 debug 字符串表因路径变长而不同）。跟着改的只有一处：两个 bat 里的
`BUILD_DIR` 原来写死 `%HPM_SDK_BASE%\hr_project_<...>`，现在落在工程自己脚下
（`%APP_DIR%\build_hpm5300evk_flash_xip_debug`），`build.bat` 与 `flash.bat`
必须一起改。

> 🔴 **`hpm_sdk\hr_project` 那一份还在，我没有删它。** 现在磁盘上有两份固件源码，
> 只有这一份（`hr\firmware\`）的 `BUILD_DIR` 是指向自己的。**以后改固件只改这一份**；
> 另一份要么删掉、要么当成只读的历史快照 —— 两份一起改必然漂移。

## 硬件与接线

| 模块引脚 | 接到 |
|---|---|
| VCC | **3.3 V** |
| GND | GND |
| SDA | PB03 |
| SCL | PB02 |

- ⚠️ **VCC 决定 I2C 电平**：模块自带的电平转换是按 VCC 做的。接 5 V 时总线也被抬到
  5 V，而 HPM5300 的 IO 是 3.3 V —— 必须接 3.3 V。
- ⚠️ **模块自带 10 kΩ 上拉**，不要再外挂一组（并联会把上升沿拉坏）。
- 这四根线和 MPU6050 完全一样，同一个 I2C0（`BOARD_APP_I2C_BASE`）。
- INT 引脚**没接**（跟 IMU 一样只接四根），所以固件不开任何中断使能位。
- 从机地址 `0x57`，`PART_ID(0xFF)` 应为 `0x15`。

## 串口协议

`115200 8N1`，FT2232 的 **channel B**（设备管理器里那个 `USB Serial Port (COMn)`；
COM 号会随重新插拔变，PC 侧按 `VID:PID=0403:6010` 认，不认 COM 号）。行尾 `\r\n`。

| 前缀 | 含义 |
|---|---|
| `#<text>` | 状态/横幅，人读的，PC 侧只记日志 |
| `D,<t_ms>,<red>,<ir>` | 一个样本，100 Hz，两个通道都是 18 bit |
| `E,1,<text>` | 芯片没答话 / 初始化失败 |
| `E,2,<ovf>` | FIFO 溢出计数变了 = 中间真丢了样本 |
| `E,3,<text>` | I2C 读失败（会重新初始化，拔了再插能自愈） |

行里带 `t_ms` 是必需的：`print_nb()` 拥塞时**整行丢**，只有时间戳能让 PC 侧知道
中间缺了多少 —— 少了它，「丢了一半样本」和「心率真的变慢了」在 PC 侧长得一模一样。

`red` 这一路心率用不上（心率只看 IR），一起打出来是为了 SpO₂ 和「两个通道是否
同时受扰」的诊断。

## 为什么算法在 PC 上

1. 得**看得见波形**才能诊断（手指没按实、环境光饱和、信号太弱，三种都只能从原始
   计数上看出来）。
2. 调参数是改一个 Python 常量，不是重新烧一次板。
3. 板端固件小到可以整份读完、可以逐行核对。

串口是**独占设备**（跟摄像头一样），PC 侧读线程会自己重连，不抛异常，所以网页永远
打得开。

## 配置旋钮（都在 `src/max30102.h`，改这里别再散到 `main.c`）

| 宏 | 现值 | 说明 |
|---|---|---|
| `MAX30102_LED_PA` | `0x24` = 7.2 mA | **手指按上去 IR 直流还不到 20000 counts 时先调这一个**（步进 0.2 mA） |
| `MAX30102_SPO2_CFG` | `0x27` | 量程 4096 nA、100 Hz、脉宽 411 µs（18 bit）。**改采样率要同步改 `ui/serial_hr.py` 的 `SAMPLE_RATE_HZ`** |
| `MAX30102_FIFO_CFG` | `0x0F` | 不平均、**回卷关**、几乎满阈值 15 |
| `POLL_PERIOD_US` | 500 µs | 20 倍过采样（FIFO 每 10 ms 进一个样本） |

两处与 Maxim 参考固件**故意不同**（理由写在 `src/max30102.h` 文件头）：
中断使能位全关（INT 没接线，开了只挂一个没人清的状态位）；FIFO 回卷关（开着会静默
覆盖最老的样本且 `OVF_COUNTER` 不计数，丢数据丢得看不出来）。

## 构建 / 烧录

```bat
cd hr\firmware
build.bat            :: 生成 + 编译，软浮点（默认，就是板子上跑的那份）
flash.bat            :: 烧进板上 QSPI NOR（先跑 build.bat）
flash.bat reset      :: 只复位重跑
```

（这两个 bat 靠 `%~dp0` 认自己的位置，所以整个 `hr\` 目录可以搬到任何地方。）

热路径里一个浮点都没有（帧里是原始计数），所以默认的软浮点构建就是正式那份；
`hf`（硬浮点）只是和 CAN 工程对齐用的，**不烧**。

产物：`hr\firmware\build_hpm5300evk_flash_xip_debug\output\demo.elf`
（在工程自己脚下，跟着工程走）。

## PC 侧对应

`dms_project/ui/serial_hr.py`（纯 `math`，没有 numpy）。常量对照：

| 常量 | 值 | 为什么是这个值 |
|---|---|---|
| `SAMPLE_RATE_HZ` | 100 | **必须等于板端 `MAX30102_SPO2_CFG` 选的采样率** |
| `BP_LOW_HZ` / `BP_HIGH_HZ` | 0.65 / 3.5 | 4 阶巴特沃斯高通 + 单节低通 |
| `MIN_BEATS` / `BEATS_KEPT` | 4 / 8 | 少于 4 次搏动不出数（「攒心跳中」） |
| `MAX_IBI_SPREAD` | 0.20 | 质量闸。⚠️ **它分不开好和坏** —— 见下面那段更正 |
| `IBI_FRESH_S` | `MAX_IBI_S × 2.5` = 4.0 | 2026-09-26 加的主路**时效**。没有它，信号一没主路就把上次的中位数一直报下去（屏幕上冻住不动的那个数） |
| `AC_MIN_RMS` | 20.0 | 2026-09-26 加的带通交流下限。峰值检波的阈值是相对量，噪声里照样"找得到"搏动，只能靠这个绝对尺度拦 |
| `FINGER_DC_MIN` | 20000 | 手指没按上去时 IR 直流只有几千 —— 低于它就是「没手指」，**一个数都不出** |
| `STALE_S` / `REOPEN_S` | 1.5 / 3.0 | 串口停了就报停；3 s 后重开串口 |
| `SPEC_*` | 见文件 | 2026-09-26 加的频谱兜底（10 s 窗、0.8~2.5 Hz、抽取 ÷4、最快 1 s 重算） |

> ⚠️ **2026-09-26 更正**：这一格原来写的是「量出来的：每种单独劣化都是 0.000~0.025，
> 三者叠加是 0.368，中间是 15 倍空档」。那个空档**只在合成的"每种劣化单独出现"上成立**，
> 真实数据上不成立 —— 真人噪声段散度 0.314 而误差只有 −2.4，合成"没救了"档散度 0.254
> 而误差 +9.5。也就是说：**多检和漏检在间隔序列上长得一模一样**，测"间隔规不规整"
> 回答不了"这个率准不准"。调阈值救不了，所以才有频谱兜底（多检/漏检都不挪动基频）。
> 证据表和推导都在 `ui/serial_hr.py` 里 `MAX_IBI_SPREAD` / `SPEC_*` 那两段注释。

`hr = None` 的几条来路（界面上都显示「未接入」，但原因不同，`note` 里带着）：
没插串口 / 串口没在出数 / 串口停了 / 手指没按上去 / **传感器上没搏动（交流 < `AC_MIN_RMS`）**
/ 攒心跳中 / 两条路都说不出话。

⚠️ **「一个 D 样本都没进来」和「手指闸没过」在屏幕上完全一样**，只能靠原始轨迹分开，
而且判序必须先看「有没有样本」再看「手指」—— 直流恒 0 时按「低于门槛」往下判，
会得出「手指没按实」的结论，方向和真因正好相反。跑 `hr\probe.bat`。

## 没做的 / 边界

- **SpO₂ 没标定**：`red` 通道一直在打，但没算 R 比值，界面上血氧那一格是静态的 ——
  给一个没标定过的数等于编数。
- **温度寄存器没读**（`0x1F`/`0x20`）。
- 🔴 **未坐实：屏幕上一度卡在 119.9 BPM 不动**（30 秒实测 min = max = 119.9、100% 有数）。
  主假设是**双计**（一次心跳数成两次，真实约 60）—— 双计给出的间隔极规整，质量闸拦不住。
  要坐实得开串口看 `beat_times` 的相邻间隔与频谱值对不对得上。
- 首次在真人手指上采数时，第一件事是看 IR 直流落在哪：不到 `FINGER_DC_MIN` 就先调
  板端 `MAX30102_LED_PA`（`src/max30102.h`，步进 0.2 mA）。
