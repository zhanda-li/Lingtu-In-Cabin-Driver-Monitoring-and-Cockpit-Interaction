# PPT制作交接：灵途智行

## 核心主张

**用身体时序、面部几何与眼嘴视觉分类形成可解释疲劳证据，把驾驶员状态感知连接到情感化座舱交互，并在RK3568单主控落地运行。**

建议采用“问题→方案→算法协同→系统闭环→实验支撑→边缘实机”的叙事。下列内容可直接拆成展示页。

| 必须回答的问题 | 可直接使用的讲解 |
|---|---|
| 1. 项目是什么 | 面向智能座舱的多模型融合驾驶员状态感知与情感化交互系统 |
| 2. 解决什么问题 | 单帧、单一观测难以解释复杂疲劳表现；把身体动作趋势、眼睑闭合、嘴部状态和头姿共同纳入决策 |
| 3. 核心创新 | 多尺度感知、相关证据分组、时间持续与冲突管理、可解释L0–L3及交互闭环 |
| 4. 算法架构 | Pose33点→45×132 Transformer；Face478点→几何/LR及同源ROI→Eye/Mouth分类→五组证据融合 |
| 5. YOLO增加什么 | 两眼分别睁闭概率、嘴部Yawn/No Yawn外观概率，为几何特征提供一致性/冲突证据；分类模型，无新增目标框任务 |
| 6. 如何融合 | 先组内几何/分类共识，再五组序数合成；相关LR/Eye取最大；有效性、持续性和降级滞回共同约束 |
| 7. 风险如何形成 | 保留Legacy作参考；显式选择V2后，持续眼/头姿共识及独立证据支持L0–L3，后端统一发出结果 |
| 8. UI有哪些交互 | 原座舱驾驶监测、小瑞语音、多媒体、导航；新增证据解释、模型状态、真实ACK模式切换 |
| 9. 硬件架构 | K1-MINI V2.2/RK3568B2、4GB/32GB、10.1寸MIPI触摸、UVC摄像头，Ubuntu ARM64 CPU运行 |
| 10. 有哪些实验 | 294决策×19列零差异、512组合、MRL356/371、PT/ONNX对拍、663条融合对照、五模型板端运行 |
| 11. 最值得展示什么 | 让观众看到“真实视频→证据组→等级原因→座舱反馈”，以及横屏触摸与独立预览的实机工程能力 |

## 建议12页结构

1. 项目定位：一张原座舱图、一句核心主张。
2. 驾驶员状态感知问题：身体动作、眼部、嘴部三个尺度。
3. 总体架构：采用[系统架构页](SYSTEM_ARCHITECTURE.md)的真实连线。
4. 时序建模：33×4、45帧、二分类输出；标15Hz为时间目标。
5. 眼嘴精细感知：左右眼独立，嘴部分类加MAR与持续时间。
6. 多模型融合：五组证据，展示相关证据不重复计分。
7. 风险解释：等级、原因、conflict/invalid/warmup/stale。
8. 情感化交互：小瑞、原UI、导航/媒体及语音链路。
9. 平台落地：K1-MINI、Ubuntu eMMC、MIPI/Goodix横屏。
10. 实验：用三项主证据说明原算法保护、眼分类、跨平台执行。
11. 调度工程：预览13.53FPS与推理1.49FPS分别标出。
12. 应用价值与工程展望：可解释感知闭环，集中列后续验收。

## 图表与讲稿边界

实验图必须带对象、样本数、平台、指标口径。MRL95.96%标“眼图分类参与者子集”；294×19标“回归一致性”，不是准确率。V2与Legacy的511条不同等级不是错误率，不能讲成V2更准。旧79段/三分类结果留在历史指南，不作为当前二分类模型的主结果。
