## 真实高德链路

- 搜索“天津站”返回带实际地址的候选，可用方向键和 Enter 选中。
- 选择“天津站”和“天津西站”之后，路线数为 0，“开始导航”禁用，状态为起终点已选；没有提前发起路线规划。
- 点击搜索后，真实服务返回 3 条驾车方案，地图实际绘制 3 条折线，“开始导航”启用。
- 该次最终验证的方案距离约 6.8 / 7.2 / 7.4 公里，显示约 21 / 20 / 21 分钟；这些值只记录本次响应，不固定进生产页面，未来会随服务结果变化。
- 选择第二方案后，其 aria-pressed=true、其余为 false，摘要距离同步为 7.2 公里，状态为“3 个方案 · 已选方案 2”。
- 点击开始导航，进入原有引导态，显示真实步骤文字“前方 320 米右转”，按钮变成结束导航，演示状态 sim=0。退出后保留路线。未声称车辆真的移动。

## 确定性故障和乱序检查

`tools/nav_browser_checks.js` 在隔离浏览器里通过 13 项检查。数据为明确标记的测试夹具，与上面的真实 API 结果分开：

1. 选择地点不提前发起算路。
2. 算路期间禁用开始导航和重复点击搜索。
3. 更换目的地取消旧请求。
4. 旧路线晚到不覆盖新目的地。
5. 新路线完成后恢复导航操作。
6. 输入编辑立即清除旧路线。
7. 多个同名地点需明确选择地址。
8. 方向键高亮候选，不擅自选择。
9. Escape 关闭列表。
10. 迟到搜索不重新打开已关闭列表。
11. 临时搜索失败不写入成功缓存，可重试。
12. HTTP 503 后不保留可导航的旧路线。
13. 迟到自动定位不替换手动起点。

`node tools/test_nav_flow.js` 通过：请求取消、旧结果拒绝、加载状态归属、坐标绑定和实际耗时比较。

`python tools/test_nav_backend.py` 两项通过：同名不同坐标保留、同地点重复记录去重、失败不能作为地点返回。全部使用模拟上游响应，不调用真实高德。
