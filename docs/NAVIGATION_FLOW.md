# 导航选址与路线规划交互升级

2026-10-30，按用户选择，改进“搜索地点 → 选择目的地 → 比较路线 → 开始导航”。沿用现有 `nav.html`，保留起终点竖排、地图卡片、右侧路线面板、配色、字体、导航栏、小瑞、疲劳服务区入口和独立演示控制。

## 当前流程

1. 搜索起点或目的地时展示真实高德候选和地址。可触摸选择，也可方向键高亮、Enter 选中、Escape 关闭；拼音组合期间 Enter 不提交。
2. 选中地点只确认坐标并预览地图标记。未点击“搜索路线”时，不提前算路、不自动进入导航。同名不同坐标的门店分别保留，存在多个同名候选时不自动选择第一家。
3. 点击“搜索路线”确认起终点后只发起这一趟规划；显示计算状态。返回后沿高德顺序展示真实路线，每张卡片显示距离、用时和已选状态，并根据真实 `drive_s` 比较耗时。没有可靠数字时不生成比较结论。
4. 切换方案同时更新高亮、地图视野、公里数和到达时间。“开始导航”仅对当前已确认起终点的有效所选路线启用。
5. 开始导航进入原有逐段引导；结束后保留路线供再次比较。演示需单独点击，不自动模拟车辆移动。

输入框重新编辑会清除对应的已选地点和旧路线。慢请求、旧搜索、旧路线和迟到的自动定位不能覆盖新选择。查询失败清除旧结果，显示原因，可通过原搜索入口重试。

## 实现边界

- `ui/web/nav-flow.js` 提供请求轮次/取消、坐标绑定与耗时比较；页面沿用现有接口和组件。
- `/amap/search`、`/amap/route`、`/amap/nearby` 返回协议保持兼容。后端搜索按名称和坐标去重，修复同名不同地点被吞掉的问题。
- 起点/终点每次选择均取真实返回坐标，文字输入不能直接冒充已确认坐标；路线不能跨起终点继续复用。
- 已使用的地图 `setFitView` 内边距按高德[官方地图参考文档](https://developer.amap.com/api/maps-javascript-api/reference/amap-map/map)的上、下、左、右顺序设置，避让原有右侧面板。
- 连续 GPS 定位跟随、偏航自动重算和原生导航 SDK 尚未接入。本轮实现选址、规划、方案选择与原有逐段引导，不能称为完整实车导航。IP 定位也不等于车辆精确定位。
- 服务区语音与疲劳入口保留；没有新增地点模型、训练任务或 RK3568 部署。

## 启动与回退

关闭旧服务窗口，双击 `ui/run_ui.bat`，浏览器 Ctrl+F5。先选择起点/目的地，再搜索路线、选择方案和开始导航。需要可用的高德 Web 与 JS 配置以及网络；不把私有 key 写入仓库。

改动作为独立 Git 提交保留，可通过 revert 回退；操作前保存用户自己的未提交修改，不使用 reset --hard、clean 或强制推送。
